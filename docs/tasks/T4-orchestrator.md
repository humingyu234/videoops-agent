## 1. 目标

实现一个 Agent：根据已确认 Brief 选择白名单工具，能跳过已有资产步骤、因缺信息暂停、等待长任务、恢复后继续并遵守步数/时间/额度边界。

## 2. 用户可见行为

用户只提交目标并处理必要问题/批准。已有音色时 Agent 自动复用；缺事实时准确追问；外部任务运行期间页面可以关闭。

## 3. 修改边界

确定性状态机掌握不变量，LLM 只产出受 schema 约束的候选 Brief/动作。一次最多三个阻塞问题、最多两轮；付费动作前合并确认一次。

## 4. 非目标

不做开放式代码执行、无限自主循环、多个角色 Agent、跨行业规划、自动发布或未经批准的昂贵重跑。

## 5. 验收场景

- 资料完整时从确认后自动调用真实工具并等待终态。
- 已有形象/音色时计划跳过创建动作；缺人物/事实时暂停且 Provider 调用数为 0。
- 服务在等待数字人任务时重启，恢复后仍为同一 AgentRun、同一 Provider 任务，提交次数为 1。
- 未知工具、无效参数、超步数/时间/额度时停止并请求人工，不能继续猜测。
- 取消后不再产生新动作；外部任务不支持取消时如实标记，而非伪造已停止。

## 6. 验证与证据

最低证据：正常计划、跳步、阻塞澄清、服务重启、并发唤醒、幂等、取消和预算停止的集成测试；至少一条真实异步任务恢复轨迹。
