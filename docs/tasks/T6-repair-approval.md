## 1. 目标

根据评价维度只失效必要下游，最多生成两个返工候选；无明确改善、昂贵上游变化或主观冲突时暂停并请示。

## 2. 用户可见行为

用户能看到第一版失败原因、Agent 要重做哪些步骤、保留哪些产物、预计时间/额度，以及修复前后差异。

## 3. 修改边界

首期自动闭环优先实现字幕安全区问题：只修改字幕/时间轴并重渲染。另实现事实错误或主观冲突转人工，不强求所有感知问题自动修复。

## 4. 非目标

不无限重试、不全链盲跑、不自动修改未证实商品事实、不把 Worker 恢复算成质量返工、不在 Provider 提交未知时再次 POST。

## 5. 验收场景

- Given 第一版字幕越界，When 评价拒绝，Then 只新建字幕/时间轴/渲染动作，声音和数字人底片任务 ID 不变。
- Given 第一次修复无超出测量误差的改善，Then 不再用同一策略盲试，进入人工。
- Given 事实错误，Then 请求用户修改并重新确认脚本；不能自动编造，所有依赖脚本的下游失效。
- Given 超时/额度、低置信主观冲突或已达两次返工，Then 停止并提供接受、细化标准、人工接管或结束选项。
- 最终硬门禁未通过时，批准按钮不能把它标成合格交付。

## 6. 验证与证据

需要依赖失效单元/集成测试、并发/重复批准测试、返工次数与额度停止测试，以及真实底片上的字幕故障注入 E2E。故障夹具必须标为 Demo，产物和任务状态仍来自真实链路。
