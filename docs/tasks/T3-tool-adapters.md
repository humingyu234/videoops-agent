# T3 类型化工具适配

| 元数据 | 内容 |
| --- | --- |
| 卡片状态 | `DRAFT`，T2 通过后冻结 |
| 路线状态 | `NOT_STARTED` |
| 风险等级及原因 | `RED`：外部 Provider、文件、权限、幂等、费用和两套任务模型 |
| 前置阶段 | T2 `DONE` |
| 权威来源 | 参赛设计、`API_CONTRACT.md`、`ASYNC_TASKS.md`、T1 运行证据 |
| 允许影响范围 | Agent 工具注册/适配层、既有 Service 的最小缺口、契约测试 |
| 实施/审查安排 | 按声音/数字人和时间轴/渲染两个互不重叠边界实施；主审统一错误与幂等契约 |
| 固定交付格式 | 完成项、风险、验证证据、阻塞项 |

## 1. 目标

把 Brief 校验、脚本、形象/声音选择、声音生成、数字人底片、时间轴、渲染、任务查询和质量检查包装为白名单类型化工具。

## 2. 用户可见行为

运行轨迹能显示每个真实动作的输入摘要、输出摘要、状态、耗时、错误类型、任务 ID 和产物 ID，而不是只显示聊天文本。

## 3. 修改边界

工具在后端调用既有应用 Service，继承登录身份、工作区、资产授权、额度和任务不变量；数字人任务与统一任务中心先由观察层兼容。

## 4. 非目标

不让 LLM 访问任意 URL/SQL/路径/命令，不通过后端自 HTTP，不绕过任务中心直接调用 Provider，不重写 FFmpeg 渲染器或先统一全部任务表。

## 5. 验收场景

- 每个工具有结构化输入输出、权限、幂等键、超时/费用信息、稳定错误和可重试分类。
- 资产越权在 Service 边界被拒绝，且没有 Provider 副作用。
- 相同幂等键重放只返回同一任务；提交结果未知时不能再次创建任务。
- 工具返回真实任务/资产关联，Agent 不自行伪造终态。
- 未注册工具或多余参数被拒绝并留下安全轨迹。

## 6. 验证与证据

进入阶段时生成精确计划。至少需要契约测试、跨用户负向测试、幂等并发测试、可重试/不可重试错误夹具，以及一条调用真实既有 Service 的当前边界证明。
