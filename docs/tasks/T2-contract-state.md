## 1. 目标

建立版本化 `DeliveryBrief`、`AcceptanceProfile`、`AgentRun`、计划步骤、工具调用、评价、批准和事件的最小持久化事实，使运行可暂停、恢复和审计。

## 2. 用户可见行为

用户提交目标后能得到稳定交付单；关闭页面或重启服务后，同一运行、确认内容和进度仍存在。

## 3. 修改边界

首期只支持 `image_to_digital_human_video`。确认的 Brief 变更必须新建版本；素材只保存带归属的 ID，不保存临时 URL。既有任务/资产仍是执行事实，不复制 Provider 状态。

## 4. 非目标

不做通用长期记忆、向量库、规则管理平台、多 Agent、复杂成本系统或 UI 视觉包装。

## 5. 验收场景

- Given 缺人物或音频用途不明，When 提交目标，Then Brief 保持待输入并列出稳定阻塞问题，不能进入执行。
- Given Brief 已确认，When 用户改变商品事实，Then 创建新版本；旧任务迟到结果不能覆盖新版本。
- Given Agent 等待外部任务，When Java 服务重启，Then 同一 AgentRun 保存原外部任务 ID 并可继续。
- Given 另一个用户请求该运行，Then 后端按账号/工作区拒绝，不能仅靠前端隐藏。
- Given 重复相同幂等请求，Then 只产生一个收费根动作。

## 6. 验证与证据

进入阶段时由 writing-plans 根据 T1 真实链路生成精确迁移、文件和命令。最低证据包括迁移回滚/重复执行、状态转换、跨用户、重复提交、重启恢复和迟到结果集成测试。
