## 1. 目标

以 `/agent` 作为默认参赛入口，清晰展示目标、计划、缺失信息、真实工具、外部任务、评价、返工、批准和最终视频，并准备可公开复现的 GitHub 项目。

## 2. 用户可见行为

新用户从一个交付目标完成整条主链；运行中可关闭页面后返回；失败原因、修复范围和人工选项清晰。Studio 从默认导航隐藏但可用于人工接管。

## 3. 修改边界

复用已有上传、素材选择、任务状态、预览和下载组件；不大规模删除旧页面。Demo 模式与真实 Provider 模式在 UI、日志和 README 中明确区分。

## 4. 非目标

不恢复所有运营页面，不把 RunningHub/Avatar Space/Electron 纳入主演示，不自动发布外部平台，不用录屏或静态数据冒充运行态。

## 5. 验收场景

- 成功场景：真实目标到真实 MP4，并显示真实任务/产物与评价证据。
- 自动修复：字幕故障夹具被定位并局部修复，上游任务 ID 不变。
- 转人工：低置信主观标准不盲目重跑，用户可接受、细化或接管。
- 恢复：等待 Provider 时重启服务，回到页面后同一运行继续且提交次数为 1。
- 安全/权限：跨用户不可见；未批准不进入最终交付；公开 Git 索引无秘密或私有地址。
- 新环境按 README 可启动 Demo 模式；真实模式的外部依赖和未包含模型如实说明。

## 6. 验证与证据

至少包括：浏览器 E2E/视频、真实运行轨迹、重启恢复记录、跨用户/幂等/批准边界测试、最终 Secret 扫描、许可证/第三方声明、干净环境 README 演练。README、Demo 视频和代码能力声明必须指向同一最终提交。
