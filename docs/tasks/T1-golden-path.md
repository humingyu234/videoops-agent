## 1. 目标

用固定样例跑通当前真实链路：

```text
登录
→ 说需求并生成文案
→ 确认文案
→ 选择 ready 人物形象和 origin 原声音
→ IndexTTS2 生成并确认声音
→ ComfyUI 生成数字人底片
→ 创建时间轴项目和初始字幕
→ FFmpeg 渲染
→ 预览并下载最终 MP4
```

固定样例使用目标 30 秒的中文商品介绍、9:16、烧录字幕，一张已入库人物图和一个已入库原声音。T1 同时锁定实际 ComfyUI 工作流、模型加载节点与文件哈希。

## 2. 用户可见行为

- `/studio` 完成“说需求→确认文案→选择形象与声音→生成并确认声音→生成底片→时间轴→预览下载”七步。
- 文案响应明确为 `modelMode=deepseek`，不能用知识回退冒充。
- 形象/音色来自真实 `/api/portraits` 和 `/api/voices?voiceType=origin`。
- 声音能试听并确认；数字人底片能预览；最终项目能读取 `outputs/latest` 并下载真实 MP4。
- 时间轴创建时生成主视频轨和按文案切分的初始字幕轨。

## 3. 修改边界

T1 只诊断、配置本地环境、执行现有链路和记录证据。发现产品缺陷时记录最小复现、影响、建议修复切片和阻塞关系；未经重新定范围不在 T1 修改运行时代码。

两套任务事实必须分别记录：声音/底片使用 `av_dh_generation_job`，时间轴渲染使用 `av_ai_task`。不能把它们合并描述成一套已统一状态机。

## 4. 非目标

- 不开发 `/agent`，不合并 Avatar Space 分支，不改数据库结构、任务模型或 Provider。
- 不启动、停止或重启来源不明的进程；当前未知 `8080` 进程必须保留，后端使用 `18080`。
- 不伪造任务、素材、成功状态、模型名称或运行轨迹。
- 不无上限重试；同一真实付费意图只允许一个稳定幂等请求。
- 不在日志或证据中写 Token、密码、签名 URL、私有配置或用户隐私。

## 5. 验收场景

### 成功场景

```text
Given：
- JDK 21、MySQL、Redis、OSS、DeepSeek、IndexTTS2、ComfyUI、FFmpeg/ffprobe 可用；
- 数据库迁移正确，当前用户有创作权限；
- 至少一个 ready 人物和一个 origin 原声音的数据库记录与 OSS 对象可读。

When：
- 用户从 /studio 完成一次固定样例；
- 对当前已经支持幂等的声音、底片、创作项目、时间轴保存和渲染动作使用稳定幂等键；问卷/文案生成接口当前不支持幂等，必须只调用一次并记录为 T3 工具适配缺口；
- 观察真实任务直到终态，不刷新步骤 0～4。

Then：
- 产生成功并已确认的 voice_generate 任务；
- 产生成功且媒体可读的 video_generate 任务；
- 产生绑定该视频任务的 creation_project；
- 产生成功的 timeline_render 任务；
- outputs/latest 的 taskId、outputAssetId 与任务详情一致；
- 最终文件为可解码 9:16 MP4，有音轨且字幕可见；音视频流时长差满足现有 0.25 秒不变量；记录目标 30 秒与实际时长偏差且内容不得被截断，T1 不新设未经样本校准的目标时长阈值；
- 记录阶段耗时、两套任务 ID、项目/资产 ID、失败点、文件 SHA-256 和 ffprobe 摘要；
- 导出实际 ComfyUI 工作流，记录 UUID、JSON SHA-256、checkpoint/LoRA 加载节点和环境标签；
- 没有重复提交真实 Provider 任务。
```

### 失败、恢复与真实性场景

- 缺 Java、Provider、OSS 或真实资产时保持未完成，记录下一安全动作，不能用 Mock 替代。
- 文案若不是明确 DeepSeek 模式，则步骤 0 失败，不能继续宣传真实模型链。
- 创建 `projectId` 前刷新导致内存上下文丢失时，记录为当前恢复缺陷；不能手工篡改状态伪造恢复。
- Provider 提交结果未知时只对账或转人工，不能再次 POST。
- 配置/测试夹具只出现 `WanVideoSampler` 不能证明具体 Wan 版本；旧分支 LTX 2.3 不能作为当前模型证据。
