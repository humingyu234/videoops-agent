# VideoOps Agent 项目定义

## 一句话目标

把现有图生数字人口播生产链变成一个能够“接单、澄清、排产、执行、验货、有限返工和请示”的行业 Agent，并用可复现证据证明它真的完成了交付，而不只是聊天界面。

## 用户如何提出目标

用户不再被迫先填完固定七步表单。首屏接受：

- 一段自然语言交付目标，例如“把这张人物图做成 30 秒中文产品介绍，竖屏、稳重、带字幕”。
- 可选人物图、参考视频、音频/音色、脚本或品牌素材。
- 明确硬约束：时长、语言、比例、截止时间、可用成本、必须/禁止出现的内容。

Agent 先把输入整理为结构化 `DeliveryBrief`。只追问阻塞执行或显著影响结果的问题；其余采用可见默认值，并允许用户一次确认或修改。

首期只支持 `image_to_digital_human_video`。大模型负责从自然语言提取候选字段，后端确定性规则负责判断是否完整；一次最多集中询问三个阻塞问题、最多两轮。缺少人物、音色用途不明、事实不足、约束冲突、权限/归属/格式/安全失败时必须暂停。中文、9:16、开启字幕等默认值可以不追问，但必须在确认卡中展示。

商品功效、价格、资质和品牌事实只能来自用户确认资料，Agent 不搜索或编造。用户上传音频时必须确认它是“克隆音色的参考录音”还是“最终旁白”；当前链路不支持的用途要明确阻塞，不能暗中替换。

## 主链路

1. 理解目标并形成 Delivery Brief。
2. 选择已有形象/音色，或让用户上传素材。
3. 生成并确认脚本与执行计划。
4. 调用既有数字人、时间轴和渲染能力，持续观察异步任务。
5. 用确定性媒体检查、规则检查和视觉/语义评价生成可解释报告。
6. 对可定位问题最多自动返工两次；无改善或超预算立即请示。
7. 用户确认后交付视频、评价报告和完整执行轨迹。

## 独立运行边界

公司项目只作为一次性脱敏代码基线。VideoOps Agent 的 Git 历史、MySQL 数据、Redis 任务状态、用户与权限、生成任务、秘密配置、存储命名空间、后端进程和端口必须独立；运行时不得依赖旧 8080 或 `ai_video` 数据库。

GPU、ComfyUI、IndexTTS2、模型权重、LoRA、数字人口播工作流以及必要的 OSS/网络基础设施可以作为外部 Provider 继续复用。调用链固定为：VideoOps 自己创建并持久化任务，经可配置 Provider Adapter 直接提交到外部模型服务，保存 external task/prompt ID，查询结果后把产物登记到 VideoOps 自己的数据与存储命名空间；不得经由旧业务后端或回写公司业务库。共享 OSS 时必须使用独立 bucket 或强制 object key 前缀。

黄金链若需要已有形象、声音或对象，只允许后续按来源许可做一次性、最小化、脱敏导入。导入完成后不得继续回读旧数据库；模型权重和 GPU 环境不复制到本仓库。

## 用户标准与自动验收的边界

Agent 使用三类证据判断结果：

- 确定性媒体门禁：可播放、容器/编码、比例、时长、音轨和文件完整性。
- 内容与版式门禁：确认事实、必用/禁用内容、字幕完整/安全区以及画中画规则。
- 感知与主观评价：身份、口型、音色、稳定性和风格接近程度。

前两类硬门禁失败不能交付。感知评价必须给出时间段、画面或文本证据和置信度；单个模型分数不能独立触发自动返工。Agent 无法天然等同用户审美，因此把主观偏好写入版本化 `AcceptanceProfile`，最终仍由用户批准。没有真实样本校准前不写拍脑袋的感知阈值。

一个运行包含一个初始候选和最多两个质量返工候选。字幕问题只重做时间轴与渲染；事实变化先由用户重新确认脚本；无改善、超时、超额度、无法定位或只剩低置信主观分歧时立即转人工。

## 界面取舍

### 默认保留

- `/agent` 单一交付入口、运行轨迹、批准卡片和结果页。
- 登录、账号归属、形象/音色选择或上传、任务中心的必要状态、视频预览和下载。
- 后端认证、资产、音色、任务、数字人、时间轴和渲染服务。

### 暂时隐藏但不删除

- 原七步 Studio：改为内部高级编辑/人工接管入口，不出现在参赛默认导航。
- 运营端、发现市场、完整素材库、独立任务中心页面和 Electron 壳：保留代码，首期不作为主演示依赖。
- 其他与纵切面无关的产品导航。

### 延期

- 开放式多智能体协作、通用工作流市场、复杂计费、多供应商自动竞价。
- 从对话直接生成全新形象。首期使用已有形象或上传图片。
- 自动发布到外部平台。

## 形象空间分支的处理

缓存分支 `origin/codex/avatar-space-provider-router@c15f55b` 不直接合并。保留并迁移的设计思想包括：异步任务、工作区/归属校验、私有 OSS、签名预览、人工确认后保存形象。暂不迁移旧任务引擎、SQL、开发配置和本地 Demo provider。

该分支的“AI 对话”目前是规则式关键词整理，“图像生成”目前是 Java AWT 绘制的 Demo PNG，并未读取源图像像素。因此首期把它定义为可选后续工具，而不是参赛核心智能能力。

## 完成标准

参赛纵切面同时满足以下条件才算完成：

- 一个新用户能从目标和素材开始，在同一主流程得到可下载数字人口播视频。
- Agent 至少完成一次真实的计划、工具调用、异步观察、质量判断和条件分支，不靠前端定时器或硬编码成功。
- 每个动作都有输入摘要、输出摘要、耗时、状态、失败原因和关联任务/产物。
- 自动评价给出证据和失败维度；返工有明确修复目标，最多两次。
- 人工批准点能阻止不合格或高风险结果继续发布。
- 至少一条成功场景、一条自动修复场景和一条转人工场景可重复演示并有测试或运行记录。
- 旧 8080 运行或停止都不影响 VideoOps 管理自己的任务；`ai_video` 不可用时，VideoOps 仍能使用自己的数据库、Redis 与存储命名空间，在外部 GPU Provider 可达时完成生成。

主演示固定为四条可验证证据：资料完整的正常成功；字幕越安全区后只重做时间轴/渲染；主观标准低置信时主动转人工；等待真实 Provider 时重启服务后继续同一任务且提交次数仍为 1。故障注入必须标为 Demo Fixture，不能用假日志或硬编码状态冒充。

效果评测使用固定且可回溯的数据集：至少 10 个商品 Brief、资料缺失/禁用词/Provider 超时或未知/字幕越界四类故障，以及一个服务重启案例。记录闭环成功率、首次通过率、自动修复率、人工操作与批准次数、局部重做及上游复用率、总耗时与 Provider P50/P90、额度/成本、误报/漏报、恢复率和重复收费根任务数；重复收费根任务目标为 0。没有当前样本与运行证据时，不预写效率提升结论。

## 非目标

首期不追求恢复原工作台所有页面、不追求任意视频创作、不追求无人监督无限执行，也不把 UI 包装或模型调用次数当作 Agent 能力证明。
