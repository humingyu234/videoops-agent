# VideoOps Agent 分阶段施工路线

本文件只维护全局路线、阶段依赖和粗粒度状态。当前正在做什么以 [EXECUTION.md](EXECUTION.md) 为准；每阶段的冻结边界和验收记录以 [tasks/](tasks/) 为准；设计理由见 [DECISIONS.md](DECISIONS.md)。

## 状态语义

- `NOT_STARTED`：尚未开始，没有可依赖的实施证据。
- `IN_PROGRESS`：正在调查或实施，仍有必做项。
- `VERIFYING`：实现或操作已完成，但强制验证尚未全部通过。
- `BLOCKED`：当前范围内已没有可继续的安全动作，且明确记录了外部阻塞。
- `DONE`：成功与反向验收都有匹配当前源码的证据。
- `NEEDS_REVALIDATION`：过去完成过，但相关源码、配置、环境或验收标准已变化。
- `DEFERRED`：项目负责人明确移出当前范围。

同时最多一个阶段处于 `IN_PROGRESS`、`VERIFYING` 或 `BLOCKED`。依赖阶段为 `NEEDS_REVALIDATION` 时，后续阶段不能依赖其行为继续施工。未来阶段卡保持 `DRAFT`，进入该阶段时再根据当前源码冻结。

## 施工顺序为什么这样排

```text
先证明旧工厂真实可生产
  -> 冻结交付单和可恢复运行状态
  -> 包装真实生产工具
  -> 让 Agent 受约束地编排
  -> 建立验货标准
  -> 建立局部返工与请示
  -> 最后完成默认页面和比赛证据
```

这样不会先做一个漂亮聊天页，再发现底层任务无法恢复或真实 Provider 根本跑不通。前端 `/agent` 放在 T7 收口，但 T2～T6 可以提供最小 API/测试入口验证真实行为。

## 修改面与工作量预估

- 前端改动为中等：新增 `/agent` 交付/轨迹/批准/结果纵切面，复用上传、素材选择、任务状态、预览和下载；调整默认路由和导航，不大规模删除 Studio。
- 后端改动为中高：新增 Agent 数据、状态机、工具适配、恢复、评价和返工；已有认证、资产、Provider、任务和 FFmpeg 生产链尽量不改。
- 旧形象分支首期不合并，只把异步候选、私有资产、人工确认和保存的设计作为后续工具参考。

在一名开发者全职、AI 辅助且现有外部环境可用的假设下：T1 通常 1～3 个工作日，环境异常可能 3～10 日；能证明 Agent 本质的窄场景 MVP 约 8～12 日；包含恢复、评价、局部返工、页面和发布证据的参赛版约 18～28 日。边学习边实施可按 25～40 日预留。这些不是承诺；T1 后必须用真实阶段耗时与 Provider P50/P90 更新，不拍脑袋承诺固定生成分钟数。

## 每阶段固定节奏

1. 开工前核对项目路径、分支、HEAD、工作区、`EXECUTION.md` 和当前阶段卡。
2. 未来阶段卡进入施工前，依据当前源码补齐规格和 writing-plans 详细计划，再从 `DRAFT` 冻结为 `ACTIVE`。
3. 一次只推进当前阶段；新发现且不阻塞的问题进入 backlog，不顺手扩展范围。
4. 改变行为时先设计最小边界证明；实现后检查 diff，运行项目原生检查并实际穿过改变的边界。
5. 证据必须说明验收项、真实/Demo/Mock 环境、源码状态、执行命令或任务、结果。
6. 只有成功和必要反向场景均成立才标记 `DONE`；未运行的真实 Provider 或端到端验证必须写成 `NOT_RUN`。

## 收口规则

- 同一质量问题最多两个返工候选；同一无变化失败最多重试两次。
- 新需求若不能增强主链的自主决策、真实执行、恢复、可观察性或质量证据，默认进入 backlog。
- T1 未完成前不实现复杂 Planner；T4 未完成前不做多 Agent；T5 未完成前不宣称自动验收；T7 未通过发布门禁前不公开推送。
- 阶段证据失效时必须转为 `NEEDS_REVALIDATION`，不能沿用旧截图或旧测试结果继续施工。
