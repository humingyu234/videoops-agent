# VideoOps Agent 实施计划

每个任务只在其验收信号成立后完成。优先做一条真实纵切面，不并行重做原产品全部页面。

| 任务 | 交付切片 | 非目标 | 验收信号 | 状态 |
| --- | --- | --- | --- | --- |
| T0 | 建立无历史、脱敏、可追溯的新仓库基线 | 不改产品功能、不合并旧分支 | 来源提交有记录；密钥扫描无未处置高风险项；本地基线提交存在 | 完成 |
| T1 | 跑通现有人工黄金链：选形象/音色→脚本→数字人→渲染→下载 | 不做 Agent UI | 真实开发环境完成一次端到端运行，记录任务 ID、产物、耗时与失败点 | 待开始 |
| T2 | 定义并持久化 `DeliveryBrief`、`AgentRun`、`Action`、`Approval`、`Evaluation` 最小契约 | 不做通用记忆/多智能体框架 | 状态机、归属、幂等和失败规则有迁移与契约测试 | 待开始 |
| T3 | `/agent` 目标输入、最少追问与计划确认 | 不复刻七步表单 | 三类典型目标能形成稳定 Brief；缺少阻塞字段才追问；用户可确认/修改 | 待开始 |
| T4 | 最小编排器调用既有 Service 并观察异步任务 | 不通过后端自 HTTP 调用、不重写 provider | 一次运行能创建真实任务、等待终态、关联产物；超时/失败可恢复 | 待开始 |
| T5 | 可解释质量评价 | 不先训练新模型、不用单一黑盒总分 | 分辨率/时长/音轨等确定性检查与内容评价分开记录；报告能定位失败维度 | 待开始 |
| T6 | 有界局部返工与人工批准 | 不无限重试、不整条盲目重跑 | 一条失败案例只重做必要步骤；最多两次；无改善/超预算进入人工批准 | 待开始 |
| T7 | 参赛演示与公开仓库首屏证据 | 不夸大 Demo 能力 | 成功、自动修复、转人工三条脚本可复现；README、架构图、测试和短视频一致 | 待开始 |

## 每个任务的固定开发节奏

1. 在任务卡中写清一个可见行为、非目标、风险边界和验收信号。
2. 先找现有入口和相似实现，再确定最小改动面。
3. 先补契约/边界测试，再实现纵切面。
4. 检查当前 diff，运行项目原生检查，并实际穿过本任务改变的边界。
5. 只有证据支持验收信号时才标记完成；未运行的真实供应商或端到端检查必须明确记录。

## 首期修改量预期

- 前端：中等。新增一个 Agent 主页面并调整导航，复用上传、选择、进度、预览和下载组件；不大规模删除旧页面。
- 后端：中高。以新增 Agent 控制面、状态持久化、事件监听和工具适配为主；预计大部分生成链保持不变。
- 旧形象分支：首期不合并。只保留已有形象选择/上传；后续按当前主线任务引擎重新移植候选生成与批准闭环。

## 收口规则

- 同一自动返工最多两次，同一无变化失败最多重试两次。
- 新需求若不能增强主链的自主决策、真实执行、可观察性或质量证据，默认延期。
- T1 未完成前不做复杂 Planner；T4 未完成前不做多 Agent；T5 未完成前不宣称自动验收。
