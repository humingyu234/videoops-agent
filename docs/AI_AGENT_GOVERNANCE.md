# AI 协作与高风险治理

本文只在任务涉及 AI 协作方式、风险分级、独立审查、外部副作用或证据治理时读取。它不替代 `AGENTS.md`、`RULES.md`、安全边界和业务契约，也不是所有任务的冷启动前置。

## 1. 治理目标

- 用最小上下文完成可验证工作，不因 Token、进度或工具限制削减安全、契约、测试和真实边界证据。
- 风险、验证和审查强度与实际影响面匹配；文档、解释和低风险局部修改不自动升级为完整规格、计划或多智能体流程。
- 任何未运行或无法运行的验证都明确记录，不能把“未验证”描述为“已完成”。

## 2. 风险分级

任务命中以下任一项即为红色高风险：

- 登录、会话、Token、角色、权限、账号归属、用户端与运营端隔离或跨账号数据范围；
- 密钥、签名、上传下载、文件预览、OSS、隐私、脱敏或未授权内容访问；
- 额度、余额、积分、计费、扣减、退回、补偿、流水或对账；
- AI Provider、外部网络、回调、Webhook、任务调度、队列、锁、幂等、重试、取消、恢复或终态；
- 数据库结构、公共 API、共享状态机、缓存键、跨模块契约、批量操作或不可逆变更；
- Electron preload、本地文件、下载、外部进程、更新或其他本地能力边界。

黄色任务会改变用户可见行为或接口消费，但已证明不命中红色条件且可回退。绿色任务是边界清楚、无外部副作用、不改公共契约且可独立验证的局部改动。风险不明确时按较高等级处理，直到证据足以降级。

## 3. 最小工作契约

非琐碎实施或审查开始前，至少明确：

1. 单一目标、允许影响范围和明确非目标；
2. 风险等级及触发依据；
3. 可观察的验收信号和必要反向场景；
4. 要读取的当前源码、契约章节和运行入口；
5. 必须运行的检查，以及不能运行时的替代证据。

会修改仓库、环境或进度时读取 `docs/EXECUTION.md`；实际施工只继续读取其中指向的当前详细计划。`docs/PLAN.md` 只用于路线、范围或依赖任务。历史规格、历史计划、完整对话和无关大文档不得作为默认上下文。

## 4. 红色任务门禁

- 先解析真实目标、账号、环境、数据范围和外部系统；目标不明确时不得写入、删除、迁移、付费调用或改变任务终态。
- 身份与归属任务验证无凭据、错误角色、跨账号和直接接口访问；文件任务验证授权、路径和签名失效；额度任务验证幂等、重复请求、流水和补偿。
- Provider、回调和异步任务验证超时、异常响应、重复通知、未知提交结果、重试和终态保护。提交结果未知时只对账或转人工，不盲目重发。
- 不可逆、批量、付费、隐私或主观质量决策必须在执行前取得明确人工确认，并记录额度、次数或影响上限。
- 当前详细计划或验收标准要求独立复核时，复核者必须基于当前 diff、运行证据和反向场景，不能仅复述实施者总结。

## 5. 证据与状态

每条关键证据至少说明：支持的验收项、`REAL/DEMO/MOCK` 环境、当前提交或 dirty diff 指纹、实际入口/命令/任务/产物、观察结果和未验证项。

- 单元或 Mock 只证明其实际覆盖的局部边界，不能代表真实 Provider、数据库、OSS、进程或端到端链路。
- 源码、配置、环境或验收标准变化后，旧证据转为 `NEEDS_REVALIDATION`。
- `DONE` 必须有与当前源码匹配的成功证据和必要反向场景；仍有安全动作可推进时不使用 `BLOCKED`。
- 日志、截图和证据禁止包含密钥、Token、密码、签名 URL、私有地址、用户隐私或未授权素材。

## 6. 有界执行

- 自动生成、重试和返工遵守产品次数、时间和成本上限；同一问题两次定向修改仍未关闭，或同一输入与环境连续两次无变化失败时，停止自动循环并报告。
- 不因“可能更完整”扩大文件、契约、数据或外部系统范围；新范围需要用户明确授权。
- 子智能体只处理可独立、无共享写入和无顺序依赖的具体任务；模型审查是证据输入，不代替负责人对验收的判断。
- 用户要求收口时停止新增探索、派发和审查，只完成已确认的必要项和一次匹配风险的验证。

## 7. Skill 与流程

- 领域 Skill 只在任务匹配时读取，统一位置见根 `AGENTS.md` 和 `docs/DOCUMENT_MAP.md`。
- 只有任务明确要求创建或更新规格、实现计划时，才使用 `.agents/skills/brainstorming/SKILL.md` 或 `.agents/skills/writing-plans/SKILL.md`。
- 不创建 VideoOps 总 Skill，不把本文件复制进 Skill，也不把通用 TDD、调试、worktree、并发或审查流程固化为项目级强制链。

## 8. 例外

偏离项目安全、权限、数据、额度、Provider 或证据边界必须由项目负责人明确批准，并记录原因、最小范围、替代控制和剩余风险。紧急修复可以先控制影响，但不能降低风险等级或省略后续验证。
