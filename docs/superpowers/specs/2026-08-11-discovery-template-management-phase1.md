# 发现页模板管理与展示（第一阶段）规格

## 1. 目标

先交付运营端对发现页工作流模板的管理能力，并让用户端发现页能展示全部已启用的工作流模板与其详情。所有模板使用 RunningHub 的唯一执行配置；用户端不暴露服务商、执行模式或配置选择。

## 2. 范围

### 2.1 本阶段交付

- 运营端模板的新增、修改、分页查询、详情查询、启用/停用与删除确认。
- 每个模板只允许绑定一个 RunningHub 执行配置；配置可随模板新增或修改，不提供版本管理、故障切换或自动服务商选择。
- 运营端维护 RunningHub 账号引用所需的最小管理/查询能力，并在模板配置中选择一个账号。
- 用户端发现页模板列表、筛选/分页（按现有页面能力）和模板详情真实接口联调。
- 用户端仅展示已启用模板；详情接口也只允许访问已启用模板。
- 模板添加或修改后的可用性由运营人员在运营端人工验证并自行决定是否启用。

### 2.2 明确不做

- 不要求、也不实现 RunningHub 自动连通性或工作流测试成功后才可展示。
- 不做用户上传、创建订单、扣减额度、提交 RunningHub、回调、轮询、结果入库或任务中心联调。
- 用户端不保留 `self_hosted_comfyui`、`runninghub_ai_app` 或任何服务商/执行模式选择；运营端唯一执行配置仍可在 RunningHub Workflow 与 RunningHub AI App 之间二选一。
- 不保留多服务商选择、执行计划选择、版本管理、故障切换与自动路由。
- 不改变已完成的 C0 双主体任务运行时基础能力，后续执行阶段再接入。

## 3. 业务规则

1. 模板状态是用户端可见性的唯一发布门槛：`enabled` 的模板可在列表和详情中查看，`disabled` 的模板不可见。
2. 启用模板前，后端必须校验模板存在且存在唯一、已启用的 RunningHub 执行配置，且配置引用的账号存在且启用；不要求账号或工作流的自动测试成功记录。
3. 修改模板或执行配置不自动改变模板启用状态；运营人员人工验证后可决定维持、启用或停用。
4. 一个模板恰好一个执行配置，执行配置的提供方固定为 `runninghub`；用户端响应不得返回提供方、账号密钥、工作流标识、节点标识、任务标识或旧的执行选择字段。
5. 运营端模板、执行配置和账号操作必须保留框架规定的权限与操作审计；敏感账号凭据不得明文返回。

## 4. 接口与页面

### 4.1 运营端

- 模板列表：支持分页、名称/状态等既有筛选，包含加载、空、失败与权限不足状态。
- 模板编辑：基本资料、分类/标签、展示素材、启用状态和唯一 RunningHub 执行配置；明确提示“请先人工验证，再启用给用户展示”。
- 模板详情：展示完整运营信息与配置摘要，但敏感凭据脱敏。
- RunningHub 账号：提供模板配置可选择的账号列表和必要的新增、修改、查询能力；不在本阶段发起自动测试。

### 4.2 用户端

- 发现页从真实后端读取已启用模板，保留加载、空、失败和分页状态。
- 模板详情从真实后端读取已启用模板的展示信息和创作表单定义。
- 页面不展示或请求 `self_hosted_comfyui`、`runninghub_ai_app`、`providerKind`、`executionMode`、`executionPlanId`、`templateVersionId`、`workflowId`、`webAppId`、`nodeId`、`runningHubTaskId`。

## 5. 数据与契约调整

- 公共可见条件从“模板、配置、账号均启用且三份测试修订一致”收敛为“模板、唯一执行配置和其账号均启用”。
- 保留现有 `WorkflowTemplate`、`WorkflowExecutionConfig`、`RunningHubAccount` 的单配置模型；不新增版本或路由表。
- 对用户端 DTO/VO 保持既有禁用字段清单，且不新增等价泄漏字段。
- `docs/API_CONTRACT.md`、`docs/DOMAIN_MODEL.md`、`docs/ASYNC_TASKS.md` 与用户端 wire 禁用字段契约必须同步本规格。

## 6. 验收

1. 运营人员可创建含唯一 RunningHub 执行配置的模板，修改后可在列表和详情中查询，并可启用/停用。
2. 停用模板立即不再出现在用户端列表，直接访问用户端详情也被拒绝。
3. 启用模板时，缺失或停用的执行配置/账号会被拒绝；存在运行中测试缺失或失败记录不会阻止启用。
4. 用户端能展示所有满足启用条件的模板卡片和详情，不出现服务商或执行配置选择控件，不接收禁用字段。
5. 运营端和用户端均覆盖加载、空、失败、权限不足（运营端）与分页状态。
6. 后端至少覆盖模板可见性、启用校验、单配置约束、权限/账号归属与用户 DTO 禁用字段；前端至少覆盖接口映射和各状态渲染。

## 7. 风险与后续阶段

- 本阶段采用人工验证，错误配置仍可能在后续实际执行时失败；运营流程需在启用前完成人工验证。
- 第二阶段再实现上传、订单、任务执行与 RunningHub 交互，并在进入执行前复核配置/账号启用状态。
