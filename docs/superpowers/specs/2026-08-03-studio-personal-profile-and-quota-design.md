# 创作端个人信息与个人积分查询设计

## 目标与范围

登录创作端后，左下角展示当前登录用户的个人信息，并从后端读取该用户自己的积分账户。当前任务只做查询，不创建账户、不补余额、不写流水，也不包含组织、团队或其他主体。

成功标准：

- 个人信息复用登录阶段已经获取的 `GET /api/auth/me` 结果，不重复请求。
- 积分通过 `GET /api/quota/account` 获取，前端不传用户编号。
- 后端只按当前登录用户查询个人积分账户，全程零写入。
- 账户不存在时返回 `46135 QUOTA_ACCOUNT_NOT_FOUND`，前端明确提示联系管理员，绝不显示为 0。
- 所有积分值以十进制字符串传输和处理，避免 JavaScript 精度损失。

## 已确认取舍

采用“个人信息复用现有登录状态 + 新增个人积分只读接口”的方案。积分卡展示总积分、可用积分和已用积分；已用积分由账户字段直接返回，本阶段只初始化为 `0`，不增加累计、扣减或统计逻辑。

评审修订（2026-08-03）：项目负责人确认 `av_quota_account` 只承载 `app_user` 个人积分账户，不再作为个人/组织共享账户。`subject_type` 固定为 `app_user`；组织工作区、组织角色或其他主体不能拥有、查询或替代个人积分账户。本接口范围与底层事实源保持一致，不预留组织额度分支。

不在本次范围内：账户创建、积分充值/扣减、积分流水、月度统计、自动轮询、组织账户、管理端配置和异步任务。

## 接口契约

### 个人信息

继续使用现有 `GET /api/auth/me`。创作端从全局初始化状态读取 `currentUser`，只消费：

- `id`
- `username`
- `displayName`

页面不展示组织、工作区或角色。主标题使用 `displayName`，为空时回退到 `username`；当两者不同时，第二行显示 `username`。

### 个人积分

`GET /api/quota/account`

- 请求参数：无。
- 身份来源：Controller 从已通过登录状态校验的会话中只取得 `appUserId`；Service 再从 `AppUser.personalTenantId` 读取个人租户编号，不使用可切换的当前工作区租户。
- 权限：`aivideo:quota:query`。
- 查询条件：当前用户的个人租户、`subject_type = app_user`、`subject_id = appUserId`、`unit_code = ai_text_credit`。
- 行为：严格只读；未命中不得插入、初始化或返回虚构的零账户。

成功响应数据：

```json
{
  "quotaUnit": "ai_text_credit",
  "availableBalance": "8640",
  "lockedBalance": "0",
  "usedBalance": "0",
  "totalBalance": "8640"
}
```

字段含义：

- `availableBalance`：当前可用积分。
- `lockedBalance`：已冻结、暂不可用的积分。
- `usedBalance`：累计已用积分；当前阶段仅持久化并返回字段，默认值为 `0`，不实施统计或更新逻辑。
- `totalBalance`：账户总积分，必须与服务端账本语义保持一致。

错误语义：

- `46135 QUOTA_ACCOUNT_NOT_FOUND`：个人积分账户不存在。
- `403`：无权查看积分。
- `401`、`46129`、`46131`：交给现有登录失效处理清理状态并跳转登录页。
- 网络、超时、`5xx` 或响应契约异常：按积分加载失败处理。

## 后端设计

在 `ai-video-core` 按 RuoYi 的 Entity、Mapper、Service 结构增加积分账户只读能力，在 `ai-video-user` 增加面向创作端的 Controller 和 VO。Controller 只负责身份入口、权限和统一响应；Service 根据当前用户标识查询唯一个人积分账户并组装结果。

`av_quota_account` 是个人积分账户唯一事实源，只允许 `subject_type=app_user`，并新增非负 `used_balance` 字段且默认值为 `0`。Service 的查询方法不得调用 `insert`、`update`、`save`、已用积分统计或任何账户初始化逻辑。未命中时抛出携带 `46135` 的业务异常。

接口不接收 `userId`、`tenantId` 或主体类型，避免越权查询其他账户。个人租户编号以 `AppUser.personalTenantId` 为唯一来源。数据库金额字段保持整数语义，响应转换为十进制字符串。

## 前端设计

新增个人积分的类型和请求服务，沿用项目现有的 RuoYi 请求封装、认证头和统一登录失效处理。React Query 仅在 `currentUser.id` 存在时发起一次查询，查询键绑定当前用户编号；不轮询，业务错误不自动重试，界面提供手动重试。

创作端页面把 `currentUser` 和积分查询状态传给 `StudioSider`。`StudioSider` 只负责展示：

- 加载中：积分数字显示 `--`，保留布局并设置 `aria-busy`。
- 成功：显示总积分、可用积分、已用积分；格式化与比例计算使用字符串/`BigInt`。
- `46135`：显示“积分账户不存在，请联系管理员”和“重试”。
- `403`：显示“无权查看积分”。
- 其他失败：显示“积分加载失败”和“重试”。

积分失败只影响积分卡，个人信息仍正常展示。删除现有静态积分、姓名和组织文案。

## 测试与验收

后端至少验证：

- 当前用户命中个人账户时返回四个约定字段。
- 账户不存在时返回 `46135`，并验证没有任何写入调用。
- 请求不能指定其他用户，查询条件来自当前登录状态。
- 无凭据、伪造或过期凭据、运营端令牌、无权限创作端角色均被真实安全链拒绝；合法 `app` 会话才能进入 Controller。
- 新增或恢复 `aivideo:quota:query` 角色映射时递增角色及受影响用户的权限修订，使迁移前会话在下一次请求时失效并重新登录。
- 超大余额仍以字符串准确返回。

前端至少验证：

- 个人信息直接使用 `currentUser`，不重复调用 `/api/auth/me`。
- 加载、成功、账户不存在、无权限和通用失败状态。
- 手动重试触发重新查询。
- 超过 `Number.MAX_SAFE_INTEGER` 的余额不丢精度，总额为 0 时比例安全。
- 页面中不再出现静态姓名、静态积分、组织或工作区文案。
