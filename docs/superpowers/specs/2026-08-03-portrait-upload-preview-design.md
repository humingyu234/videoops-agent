# 形象上传预览交互设计

## 目标

优化用户端“形象”模块的新建弹窗：选择一张人物照片后，用图片预览卡替换原上传入口；用户可以点击图片放大查看，也可以删除当前选择并重新选择。

“新增形象”和空态“上传第一张人物照片”继续打开同一个新建弹窗，因此共享同一套交互。

## 范围

- 修改 `PortraitLibraryView` 的本地待上传文件展示与操作。
- 使用 Ant Design `Upload` 图片卡片列表和 `Modal` 预览能力。
- 保留现有 JPG、JPEG、PNG、单文件、最大 10MB 校验。
- 补充组件测试及必要的局部样式。

不修改后端、上传接口、形象数据结构、服务端文件安全校验、编辑已有形象流程或批量上传能力。

## 交互设计

1. 未选择文件时，显示现有点击／拖拽上传入口。
2. 选择合法图片后，上传入口完全隐藏，原位置显示单张图片预览卡。
3. 点击预览卡中的图片或预览操作，打开大图预览弹窗。
4. 点击删除操作，仅清除尚未提交的本地文件，并立即恢复上传入口；此时不调用后端删除接口。
5. 删除后可以重新选择另一张图片。
6. 关闭新建弹窗后清空待上传文件和预览状态；再次打开时显示上传入口。
7. 文件超出 10MB 时继续显示原有错误提示，不进入预览状态。
8. 编辑已有形象时不展示上传区，行为保持不变。

## 状态与资源管理

- `fileList` 仍是唯一的本地待上传文件状态，最多包含一项。
- 预览优先使用 Ant Design 已生成的缩略图；需要时从 `originFileObj` 读取 Data URL，不创建持久化资源。
- 放大预览弹窗关闭时只关闭预览，不清除已选择文件。
- 删除或关闭新建弹窗时清理预览状态，避免旧图片在下一次打开时闪现。

## 可访问性

- 预览和删除使用 Ant Design 的可聚焦操作按钮。
- 图片提供文件名作为替代文本。
- 预览弹窗可通过关闭按钮和 Escape 键关闭。

## 风险与任务卡

- 风险等级：黄色。依据是用户可感知的上传前交互发生变化，但不改变接口、安全校验、服务端数据或实际上传时机。
- 单一目标：完成单文件选择后的预览、放大、删除与重新选择闭环。
- 允许修改：`PortraitLibraryView.tsx`、对应组件测试及该页面局部样式。
- 不做范围：后端、接口契约、公共上传组件重构、批量上传、图片内容审核。
- 实施方式：单实现者串行完成；不使用子智能体。
- 审查：针对受影响组件做一次差异检查。

## 验收与验证

- 测试验证从两个入口打开的新建弹窗均使用同一交互。
- 测试验证选择图片后上传入口消失并出现预览。
- 测试验证点击预览可打开大图。
- 测试验证删除后预览消失、上传入口恢复且可以重新选择。
- 测试验证超大文件仍被拒绝。
- 运行受影响 Vitest、TypeScript 检查和前端构建。
- 在本地工作台手动验证选择、放大、删除和重新选择。
