# LTX-2.3 数字人滚动续写实验设计

## 1. 文档信息

- 日期：2026-07-13
- 模块：数字人与声音 / ComfyUI 连续数字人执行器
- 状态：待书面规格审查
- 关联规格：`docs/superpowers/specs/2026-07-12-comfyui-continuous-digital-human-design.md`
- 实验环境：ComfyUI + LTX-2.3，物理 GPU 5，独立端口 8195

## 2. 目标

验证一种观看上无明显切点、计算上可无限滚动的 LTX-2.3 数字人生成方式。

调用方只提交一次人物图和一条完整音频，只得到一个最终 MP4。执行器内部使用带重叠上下文的窗口续写，但不把窗口暴露为分镜、独立任务或独立结果。

本实验优先验证：

1. 相邻窗口动作、构图、背景和嘴型连续。
2. 人物身份不会随着窗口数量持续漂移。
3. 单窗口显存可控，失败后可从最后成功窗口继续。
4. 最终音频仍是用户上传的完整原始音频，不产生音频拼接缝。

## 3. 非目标

- 不尝试在一次扩散采样中生成无限帧。
- 不修改或重启物理 GPU 0、6、7 上的任何进程。
- 不直接替换现有 8188 工作流。
- 首轮实验不接入 React、RuoYi、任务中心和额度系统。
- 首轮实验不承诺 1080×1920 最终质量；先验证低分辨率连续性，再开启逐窗两阶段放大。

## 4. 方案比较

### 4.1 独立分段硬拼接

每段都从原图独立生成，再用 FFmpeg 拼接。实现简单，但人物姿态、背景纹理、嘴型和随机噪声在切点处不连续，不采用。

### 4.2 单次超长 latent

将完整音频换算成数千帧，一次生成。现有 40GB A100 环境已经出现身份漂移、显存不足和异步卸载异常，不采用。

### 4.3 带重叠上下文的滚动续写

上一窗口末尾视频作为下一窗口开头的强条件，原始人物图作为低强度身份锚点，所有窗口共享同一提示词、尺寸和全局音频时间轴。采用此方案。

## 5. 固定窗口参数

- 帧率：25 fps。
- 单窗口总长度：257 帧，约 10.24 秒，满足 `8n+1`。
- 重叠上下文：33 帧，约 1.32 秒，满足 `8n+1`。
- 每窗口新增内容：224 帧，约 8.96 秒。
- 窗口步长：224 帧。
- 最后窗口：补齐到 257 帧进行推理，只保留落在完整音频时长内的有效帧。
- 所有窗口的宽高、裁切、镜像方向和色彩预处理参数完全一致。

若 257 帧在 GPU 5 冒烟测试中显存不足，只允许整体降为 193 帧窗口、33 帧重叠、160 帧新增；不得临时改变单个窗口长度。

## 6. 条件与身份锚定

### 6.1 首窗口

- 原始人物图在第 0 帧以强度 1.0 注入。
- Talking Head LoRA 强度 0.9。
- 不使用仙侠风格 LoRA。
- 不使用 `LTX2_NAG`。

### 6.2 后续窗口

- 上一窗口最后 33 帧作为当前窗口第 0～32 帧的视频 guide，强度 1.0。
- 当前窗口第 32 帧额外注入原始人物图的人脸区域身份锚点，强度初始值 0.25。
- 身份锚点只覆盖扩张后的人脸与头发区域，不覆盖身体和背景，避免整画面突然复位。
- 身份锚点强度允许在 0.15、0.25、0.35 三档中通过短片 A/B 测试选择，正式任务中保持固定。
- 若上一窗口尾部人脸相似度低于门禁，不得把该窗口作为下一窗口条件；从最近通过门禁的窗口重新生成。

## 7. 提示词规则

正面提示词固定包含：

```text
同一个人物，身份、五官、脸型、发型和服装全程保持一致；
固定机位，单人上半身自然说话，背景稳定，不切换镜头，动作连续。
```

负面提示词固定包含：

```text
different person, identity change, face morphing, inconsistent facial features,
changing hairstyle, changing clothes, extra person, camera cut, distorted face,
background change, sudden pose change
```

“人物保持一致”不得写入 negative conditioning。

## 8. 音频时间轴

- 输入音频只解码和标准化一次。
- 每个窗口按全局帧区间读取对应音频样本，重叠窗口读取相同的音频重叠区。
- 视频窗口只负责视觉与嘴型条件，不输出最终音轨。
- 拼接完成后按完整音频的真实时长裁齐视频，并一次性挂回未分段的完整音轨。
- 最终音视频时长差不得超过 0.1 秒。

## 9. 噪声与随机性

- 任务只有一个 63-bit `base_seed`。
- 每个窗口的噪声由 `base_seed` 和全局起始帧确定，不使用独立随机 seed。
- 相邻窗口重叠区必须复用相同的确定性噪声切片。
- 恢复任务时必须得到与原执行相同的窗口噪声。

## 10. 窗口合成

1. 首窗口保留全部有效帧。
2. 后续窗口的前 33 帧只用于上下文验证，不直接重复追加。
3. 在上一窗口尾部与当前窗口上下文之间计算人脸关键点、嘴部开合、颜色差和光流残差。
4. 默认直接从当前窗口第 33 帧开始追加新内容。
5. 若边界残差超阈值，只允许在嘴部以外区域做最多 4 帧的光流对齐融合；嘴部不得双帧透明叠加。
6. 超过融合能力时重试当前窗口，不以长交叉淡化掩盖错误。

## 11. 执行与持久化

- 仅在 `CUDA_VISIBLE_DEVICES=5` 的 8195 隔离实例运行。
- 每个任务目录保存 `manifest.json`、原始输入哈希、窗口计划、prompt ID、seed、guide 参数、窗口视频和质量指标。
- 每完成一个窗口，先写临时 manifest，`fsync` 后原子替换。
- 取消操作只在当前窗口安全结束后停止调度，不发送强制 CUDA 中断。
- 窗口失败最多自动重试两次；仍失败则任务进入 `interrupted`，保留已通过门禁的窗口。
- 恢复时从第一个未通过门禁的窗口继续。

## 12. CUDA 稳定性约束

- 首轮实验绕过 `LTX2_NAG`，避免现有量化权重迁移和异步 offload 异常。
- 禁止在采样中途强制中断后立即提交新任务。
- 每个窗口完成后检查队列、GPU 显存和 ComfyUI history，再调度下一窗口。
- 出现 OOM、`invalid argument` 或 pinned tensor 状态异常时，停止任务并标记实例不健康，不在同一 CUDA 上下文继续重试。
- 8195 使用独立数据库、日志和 PID 文件，不共享 8188 数据库。

## 13. 接口草案

沿用关联规格的任务接口，首轮增加实验参数但不允许客户端指定 GPU：

```http
POST /ai-video/ltx23/continuous-generate
```

```json
{
  "portrait_image": "multipart file",
  "source_audio": "multipart file",
  "prompt": "string",
  "base_seed": 42,
  "window_frames": 257,
  "overlap_frames": 33
}
```

生产环境中 `window_frames` 和 `overlap_frames` 由服务端配置固定；接口字段仅用于 GPU 5 实验，不进入公开业务契约。

## 14. 质量门禁

每个窗口必须通过以下检查：

- 只有一个主脸，且主脸在有效帧中的检测覆盖率不低于 95%。
- 人脸 embedding 与原图的余弦相似度中位数不低于 0.60，任意连续 1 秒均值不低于 0.50。
- 窗口末尾 33 帧与下一窗口上下文的身份相似度差不超过 0.05。
- 接缝前后人物中心位移不超过画面宽度的 3%。
- 接缝前后背景非人物区域的平均颜色差不超过 8/255。
- 不出现黑帧、重复音频、重复新增帧或帧时间戳倒退。

阈值必须先用同一人物的 15 秒良好基线进行校准；正式长片门禁不得低于基线相似度第 10 百分位减 0.05。

## 15. 实验顺序

1. 5 秒、121 帧单窗口基线，确认模型、Talking Head LoRA 和提示词正常。
2. 约 19.2 秒三窗口测试，验证两个接缝和身份锚点。
3. 约 60 秒七窗口测试，验证身份漂移趋势和恢复机制。
4. 94 秒真实音频测试，验证现有失败场景。
5. 通过低分辨率门禁后，再启用逐窗口两阶段空间放大。

任何阶段失败都停止扩大时长，不跳过短片基线直接跑完整音频。

## 16. 验收标准

- 调用方只创建一个任务并获得一个最终 MP4。
- 60 秒和 94 秒测试均没有可感知的硬切、黑帧或重复音频。
- 人物身份指标满足质量门禁，且相似度不随窗口序号单调下降。
- 最终音频与输入完整音频一致，时长误差不超过 0.1 秒。
- 任务可在窗口边界取消和恢复，已通过门禁的窗口不重新生成。
- 测试期间物理 GPU 0、6、7 没有出现本服务进程、显存新增占用或进程重启。

## 17. 依据

- LTX 官方推理支持视频扩展、多条件媒体与指定条件起始帧；长视频 guide 帧数需要满足 `8n+1`，目标帧位置需要按 8 对齐。
- ComfyUI-LTXVideo 的 `LTXVAddGuideAdvanced`/`LTXVImgToVideoAdvanced` 支持在指定帧注入图像或视频 guide，并控制 strength 与 attention mask。
- LTX-2.3 官方两阶段 pipeline 使用空间 latent upsampler，适合在连续性验证后逐窗启用高分辨率阶段。
