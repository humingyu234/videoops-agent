# 用户自有声音直接删除设计规格

## 1. 结论与用户决策

本规格为数字人工作台“声音”模块补充单条删除能力，并作为
`2026-08-03-voice-upload-local-whisper-transcription-design.md` 的增量契约。用户已确认：

- 不检查声音是否被作品引用。
- 不进入回收站，不提供恢复入口。
- 只允许用户删除当前租户、当前工作区中属于自己的声音。
- 公共声音即使出现异常同归属数据，也不能通过用户端接口删除。
- 删除产品效果为永久消失；对应音频资产在数据库中立即不可访问，并在提交后尝试物理清理存储对象。

“直接删除”在技术上定义为：`av_voice` 按项目规范执行逻辑删除，用户侧所有查询、试听、编辑、
重试和转写写回立即不可达；声音独占的资产记录及 OSS／本地对象在数据库提交后清理。逻辑删除记录
只用于框架一致性和审计，不构成回收站，也不提供恢复 API。

## 2. 目标、范围与不做范围

### 2.1 单一目标

当前创作端用户可以在声音列表中确认并删除自己的一条声音；删除成功后该声音立即从页面和所有
用户端声音接口消失，其他用户、其他工作区及公共声音不能被删除。

### 2.2 必须实现

- 用户自有声音卡片提供“删除”入口和不可恢复风险确认。
- 删除请求期间显示操作中状态并阻止重复提交。
- 删除成功后停止相关播放、退出编辑／展开状态、移除列表项并修正分页。
- 用户端新增单条删除接口、独立删除权限和操作日志。
- Service 在 SQL 条件中同时校验 tenant、workspace、owner、未删除状态和声音 ID。
- 删除任何转写状态的自有声音，包括 `pending|transcribing|ready|failed`。
- 后端只允许删除 `origin|clone`，`public` 在最终条件删除 SQL 中也必须被拒绝。
- 已领取的 Whisper 租约不得向已删除声音写回结果。
- 声音和独占资产在同一数据库事务中逻辑删除，提交后清理存储对象。
- 删除成功后，旧列表／轮询响应不能把卡片重新写回页面。
- 覆盖成功、失败、重复提交、无权限、跨账号、跨工作区和转写竞态测试。

### 2.3 明确不做

- 不做批量删除、回收站、恢复、撤销、保留期或定时清理页面。
- 不检查作品、草稿或其他业务对象的引用关系；这是用户明确确认的例外规则。
- 不新增 `deleting` 状态，不改变现有转写状态枚举。
- 不新增统一任务、额度、通知或异步任务追踪。
- 不新增运营端跨用户删除接口。
- 不允许前端传入 `ownerId`、`tenantId` 或 `workspaceId`。
- 不物理删除 `av_voice` 行，不绕过 MyBatis-Plus `@TableLogic`。

## 3. 风险等级与最小任务卡

### 3.1 风险等级

本任务为红色高风险，命中用户数据删除、文件资产、资源归属、权限字典、公共 API、外部存储副作用
和不可逆操作。用户明确取消引用检查和恢复能力，不降低风险等级。

### 3.2 任务卡

- 目标：实现“仅删除自己的单条声音”，并同步清理独占音频资产。
- 允许影响：`ai-video-core` 的 `voice` Service、现有资产删除调用、`ai-video-user` 声音 Controller、
  用户端声音 Service／卡片／列表、声音权限前向 SQL、模块测试和本规格对应实现计划。
- 不允许影响：作品引用模型、其他素材删除语义、运营端、Whisper Worker 协议、转写状态、额度、任务中心、
  回收站、批量删除和用户未提交改动。
- 实施并发：最多 1 名实施者；完成后 1 名独立安全／数据专项审查者，修复后只定向复核。
- 反向验收：匿名、缺少删除权限、运营端 Token、其他用户、其他工作区、公共声音、已删除 ID 和重复请求
  均不能删除目标；删除中的重复点击只能产生一次有效请求；删除前发出的旧列表响应不能恢复卡片。
- 强制验证：后端 Service／Controller 契约测试、权限和 SQL 归属测试、转写竞态测试、前端 API／组件／页面
  测试、TypeScript、Biome、相关 Maven 测试、两个启动应用路由边界 Smoke Test，以及一次真实自有声音删除
  人工验收。

## 4. 备选方案与选择

### 4.1 方案一：逻辑删除声音，提交后同步清理资产（采用）

数据库事务只提交声音的逻辑删除；提交成功后在同一请求链路执行资产和存储对象清理。数据库状态先成为
不可达事实，避免“文件已删但声音仍可见”的破坏性中间态。存储清理失败不得复活声音，也不得向客户端
返回与实际状态矛盾的失败；记录不含用户内容的结构化错误，遗留资产由运维手工清理。

### 4.2 方案二：只逻辑删除声音并永久保留资产（不采用）

实现简单，但持续产生不可访问的孤儿文件，不符合用户要求的直接删除。

### 4.3 方案三：逻辑删除后创建后台清理任务（不采用）

可实现自动重试和可观测补偿，但会新增任务状态、调度和追踪范围，违反本次不扩展异步任务的边界。

## 5. 前端设计

### 5.1 入口与可见性

- 删除入口放在展开后的声音卡片操作区，与现有“编辑”操作同层，使用危险操作视觉样式。
- `voice.type !== 'public'` 时显示删除入口；公共演示／公共目录声音不显示。
- 生产接口当前只返回 tenant、workspace、owner 全部匹配的声音，因此线上可见记录均为本人资源；前端可见性
  只改善体验，不能代替后端归属校验。
- 编辑状态下保留“取消／保存”动作，不同时显示删除；退出编辑后可删除。
- `VoiceCard` 新增 `onDelete` 和 `deleting` Props；删除按钮必须 `stopPropagation()`，不能触发展开、播放、
  时间轴跳转或文本编辑。

### 5.2 确认与操作中状态

点击删除时使用 Ant Design `Modal.confirm`：

- 标题：`删除声音“{name}”？`
- 内容：`删除后无法恢复，音频文件和文案将同时删除。`
- 确认按钮：`确认删除`，危险样式。
- 取消按钮：`取消`。

页面使用同步 ref 锁定完整确认流程：打开弹窗前先把 `deleteFlowRef.current` 设为目标 ID；只要确认框未关闭，
其他卡片和同一卡片都不能再打开第二个确认框。`onOk` 还使用 `deleteRequestRef` 做请求互斥，返回唯一删除
Promise，由弹窗展示 loading；React state `deletingVoiceId` 只负责渲染操作中状态，不能作为并发锁。

- 取消或确认框最终关闭：清理 flow 锁。
- 请求成功：保持锁直到弹窗关闭，再清理请求锁和渲染状态。
- 请求失败：清理请求锁和渲染状态，但保留 flow 锁；当前确认框可再次确认，关闭后才允许打开其他确认框。
- 组件卸载：销毁本组件创建的确认框并清理 refs，禁止卸载后写 state。

### 5.3 成功、失败与本地状态收口

提交前若目标正在播放，调用现有单实例播放 Hook 的 `stop()`，释放当前音频；删除失败时不自动恢复播放。

服务端成功后：

- 先把 ID 写入 `deletedVoiceIdsRef` 本地 tombstone 集合，再更新列表。
- 从 `voices` 中移除该 ID，不乐观伪造服务端成功。
- 从 `expandedIds` 中移除该 ID。
- 若 `editingId` 为目标，清空编辑 ID 和草稿。
- 复用现有派生分页与页码修正 Effect；删除当前页最后一条时自动回到有效页。
- 显示成功提示 `声音已删除`。

所有 `loadVoices` 响应在 `setVoices` 前必须过滤 `deletedVoiceIdsRef`；这包括初次请求、上传事件刷新和 1.5 秒
转写轮询。这样删除前已发出的旧请求即使后返回，也不能恢复已经成功删除的卡片。页面重新加载后以后端
逻辑删除为准，无需持久化本地 tombstone。

服务端失败后：

- 保留列表、展开和编辑数据，不移除声音。
- `ApiError.code===401` 或其他会话失效码只由 adapter 清理会话和跳转，页面不再显示通用删除失败。
- 当前 adapter 对 403 只做标准化、不自动展示 UI；页面按稳定 `code===403` 只提示一次
  `没有删除声音的权限`，不按中文 `msg` 分支。
- 其他业务／网络失败显示 `声音删除失败，请刷新后重试`；取消请求不显示业务失败。
- Promise 保持 rejected，让确认框保留并结束 loading，允许用户明确重试或取消。
- 无论成功、失败还是取消，请求锁和 `deletingVoiceId` 都必须按上述规则在 `finally`／`afterClose` 收口。

## 6. 用户端 API 契约

### 6.1 权限

新增：

```text
aivideo:voice:delete
```

权限只控制操作资格，不能替代 tenant、workspace 和 `ownerId` 的 SQL 范围。前向 SQL 将权限授予现有
`personal_creator` 角色；已登录用户需在部署后重新登录或按现有会话修订机制刷新权限快照。

### 6.2 删除接口

```http
DELETE /api/voices/{voiceId}
Authorization: Bearer <app_access_token>
clientid: <app_client_id>
```

- 只装配到 `ai-video-user-api`；`ruoyi-admin` 不得暴露此 Controller。
- Controller 使用 `@SaCheckPermission(value = "aivideo:voice:delete", type = "app")` 和
  `BusinessType.DELETE` 操作日志。
- 本接口不使用 `@RepeatSubmit`：重复请求必须进入 Service，由原子条件删除保证只有一次成功，并稳定返回
  `46401`；前端同步锁只改善体验。
- 请求无 body，不接收归属字段或 `expectedRevision`。
- `voiceId` 按字符串接收并在 Service 中安全转换为正 `Long`。
- 成功返回标准 `R<Void>`：`code=200`、`data=null`。
- 同一 ID 第二次删除、已删除 ID、其他账号或其他工作区 ID 统一返回 `46401 VOICE_NOT_FOUND`，不泄露资源存在性。
- 缺少删除权限返回 403；匿名和错误端 Token 按现有创作端认证隔离处理。

前端 `VoiceApi` 新增：

```ts
delete(voiceId: string): Promise<void>
```

页面只调用模块 API，不散写路径、Header 或 envelope 解包。

## 7. 后端分层与删除一致性

### 7.1 RuoYi 分层

- `VoiceController` 只负责路径参数、创作端权限、日志、防重和 `R<Void>` 包装。
- `IVoiceService` 新增单条自有声音删除方法。
- `VoiceServiceImpl` 负责删除权限、tenant／workspace／owner 归属、逻辑删除、转写竞态和资产清理编排。
- `VoiceMapper` 继续复用 `BaseMapperPlus`／MyBatis-Plus 逻辑删除能力，不新增 Repository、application、port、
  command 或其他平行业务层。
- 不新增 BO／VO／DTO；删除请求只有路径 ID，响应没有业务 data。

### 7.2 数据库事务

Service 在事务中执行：

1. 校验 `aivideo:voice:delete` 和当前工作区可用。
2. 使用 `voice_id + tenant_id + workspace_id + owner_id + del_flag=0 + voice_type IN ('origin','clone')`
   查询目标；同归属 `public` 也按 `46401` 处理。
3. 使用包含同一归属、类型和未删除条件的 Mapper 逻辑删除；影响行数必须为 1，否则返回 `46401`。
4. 在同一事务调用资产 Service 的专用删除编排，对对应 `assetId + tenant + workspace + owner +
   category=voice_sample + del_flag=0` 执行逻辑删除，并注册提交后物理对象清理。

不得仅靠先查结果执行无条件 `deleteById`；写 SQL 自身必须包含归属和未删除条件，关闭检查与写入之间的
越权／并发窗口。

### 7.3 资产与存储清理

- `av_voice.asset_id` 在当前表上有租户内唯一约束，声音上传资产为声音独占资源，可随声音删除。
- 不能直接复用当前“先删对象、再删资产记录”的 `deleteOwnedAsset` 顺序。资产 Service 新增一个仅供已开启
  数据库事务调用的专用编排：先按 assetId、tenant、workspace、owner、`category=voice_sample`、`del_flag=0`
  逻辑删除资产行，再注册 after-commit 物理删除；不得改变人物上传失败清理等现有调用语义。
- 声音和资产逻辑删除处于同一事务。任一数据库写失败都整体回滚，且不得触发存储删除；提交成功后
  `requireOwned` 的 `del_flag=0` 条件保证详情、试听和内部读取立即不可访问。
- `av_asset` 逻辑删除行保留 objectKey，作为崩溃或物理清理失败后的持久化清理证据；不通过任何用户端接口
  暴露。提交后回调在当前请求链路尝试物理删除 OSS／本地对象。
- 外部存储调用禁止放入声音数据库事务；数据库回滚时不得清理文件。
- 存储清理失败时捕获异常并记录 voiceId、assetId、tenantId、workspaceId、ownerId 和稳定错误类型；禁止记录
  音频、文案、签名 URL、对象凭据或内部完整路径。
- 因声音和资产已提交逻辑删除，物理清理失败不向客户端返回失败、不恢复声音，也不自动新增后台任务；
  运维可从逻辑删除资产行恢复 objectKey 并手工重试。进程在提交后回调执行前退出时也可能残留不可访问的
  存储对象，这是本次“无耐久异步清理任务”边界下的明确剩余风险；规格不宣称物理删除具备崩溃后自动重试。

### 7.4 转写竞态

- `claimNext` 的候选查询和“候选转租约”条件更新 SQL 都必须显式带 `del_flag=0`；删除与领取交错时，
  只有先成功的条件写生效，删除提交后不能再领取该声音。
- 已领取 Worker 的成功／失败写回继续要求 `del_flag=0`、租约 owner、状态和修订号匹配；删除后影响行数为 0，
  结果被丢弃。
- 若资产清理与正在读取音频的 Worker 竞态，Worker 可能完成当前流或收到资产不存在；两种结果均不得写回
  已删除声音，也不得在页面产生失败记录。
- 删除不等待租约结束，不把声音改为 `failed`，也不创建取消任务。

## 8. 状态、错误与权限矩阵

| 场景 | HTTP／业务结果 | 用户端行为 |
| --- | --- | --- |
| 删除本人任意转写状态声音 | `200` | 移除卡片并提示成功 |
| ID 不存在、已删除、他人或跨工作区 | `46401 VOICE_NOT_FOUND` | 保留卡片，提示刷新后重试 |
| 无 `aivideo:voice:delete` | `403` | 集中 adapter 展示无权限 |
| 匿名、运营端 Token、错误 clientid | 认证失败 | 复用现有认证隔离处理 |
| 同一 ID 并发删除 | 仅一个 `200`，其余 `46401` | 前端本地禁重，后端条件删除兜底 |
| 同归属 `public` 声音 | `46401 VOICE_NOT_FOUND` | 不显示删除入口，直接 API 也不能删除 |
| 声音／资产数据库删除失败 | 业务失败并回滚 | 声音与资产保持原状 |
| 逻辑删除成功、物理对象清理失败 | `200` | 声音和资产保持不可见；服务端记录脱敏清理错误 |

不新增删除专用业务错误码。`46401` 继续统一表达声音不存在、已删除或不属于当前范围。

## 9. 数据库与权限迁移

新增前向 SQL，例如：

```text
20260804_01_voice_delete_permission.sql
```

迁移冻结精确基线：权限 ID `1000024`、权限码 `aivideo:voice:delete`、角色绑定 ID `1000224`、角色 ID
`1000101` 且 `role_code=personal_creator`。迁移只新增：

- `app_permission`：`aivideo:voice:delete`，`resource_type=voice`，`action=delete`。
- `app_role_permission`：授予现有 `personal_creator` 角色。

不修改 `av_voice`、`av_asset` 表结构，不增加删除状态或索引。迁移必须遵守：

- 首次执行前断言固定 ID 未被其他 code／绑定占用，权限 code 未被其他 ID 占用，目标角色精确存在且 active；
  任一冲突使用 `SIGNAL SQLSTATE '45000'` 中止，禁止 `ON DUPLICATE KEY UPDATE` 覆盖未知数据。
- 重复执行只接受权限全部冻结属性及角色绑定完全一致；完全一致时为 no-op，属性不一致时 fail-closed。
- 不修改既有 query／upload／edit／transcribe 权限及任何无关角色绑定。
- 对已存在用户的前向部署必须使目标角色和受影响用户的权限修订失效，或在维护窗口强制受影响创作端会话
  重新登录；不得通过安全排除或临时绕过授权。实现计划必须根据目标环境选择并验证一种路径。
- 验证查询必须确认权限、角色绑定和未受影响权限计数；回退只在未产生依赖时按“先精确删除角色绑定、
  再精确删除权限”的顺序执行，任何属性漂移都中止，不回退无关角色／权限修订。

## 10. 测试与验收

### 10.1 后端

- Controller 契约：`DELETE /api/voices/{voiceId}`、`type=app`、删除权限、无 `@RepeatSubmit`、删除日志和
  `R<Void>`。
- Service 成功：本人 `origin|clone` 声音和独占资产在同一事务逻辑删除一次，并在提交后请求物理清理。
- 归属反向：跨 tenant、workspace、owner 以及已删除 ID 均返回 `46401`，Mapper 写条件包含全部范围。
- 类型反向：同 tenant、workspace、owner 的 `public` 仍返回 `46401`，声音和资产均不删除。
- 权限反向：缺少删除权限返回 403，且不查询／删除声音或资产。
- 并发：第二次或并发条件删除影响 0 行时返回 `46401`，资产清理只触发一次。
- 转写竞态：候选查询后、租约条件更新前删除时，领取更新因 `del_flag=0` 影响 0 行；另覆盖写回先提交后删除、
  删除先提交后写回、租约过期恢复与删除并发，删除后声音不复现且清理仅一次。
- 外部失败：声音／资产事务回滚不清理存储对象；对象不存在、物理删除失败或回调前进程退出均不恢复
  声音和资产访问，且保留可定位的逻辑删除资产证据，不泄露用户内容。
- 非 HTTP 调用：Service 缺少删除权限时同样在 Mapper 调用前返回 403。
- 非法 ID：空白、零、负数、非数字和 `Long` 溢出统一返回 `46401`，不得查询或清理资产。
- SQL 契约：首次、重复执行、固定 ID／code 冲突、角色缺失／不一致、绑定冲突、验证查询和精确回退；既有
  四个声音权限和无关角色绑定保持不变。

### 10.2 前端

- API：DELETE 方法、ID URL 编码、标准 adapter 成功／业务失败。
- 卡片：本人原声／克隆声音显示删除，公共声音不显示；点击不触发展开／播放。
- 确认框：名称、不可恢复提示、危险按钮和取消路径正确。
- 操作中：同步 flow ref 阻止多个确认框，请求 ref 阻止多次 DELETE；Promise 未完成时保持 loading，取消、
  失败、成功和卸载均正确解锁。
- 成功：播放停止、卡片移除、展开／编辑状态清理、最后一条删除后页码有效、成功提示出现。
- 并发刷新：删除前发出的初次加载／事件刷新／转写轮询响应后返回时，被本地 tombstone 过滤，不能恢复卡片。
- 失败：卡片和文本不丢失、确认框结束 loading；401 不重复提示并执行既有会话失效，403 只提示一次且不
  移除卡片，其他业务／网络失败显示通用错误，取消请求无业务提示。
- 回归：播放单实例、时间轴跳转、文案编辑、重试、重新同步、筛选和分页继续通过。

### 10.3 人工验收

1. 登录具有删除权限的创作端账号并上传一条非敏感测试音频。
2. 在播放中点击删除，确认音频立即停止；取消一次后声音仍存在。
3. 再次删除并确认，声音从列表消失，刷新页面后不再出现，详情和试听 URL 返回 `46401`。
4. 使用另一个创作端账号直接调用同一 ID，确认返回 `46401`。
5. 使用运营端 Token 和缺少删除权限的创作端账号直接调用，确认认证隔离／403。
6. 删除一条 `transcribing` 声音，确认后续 Worker 结果不写回且页面不重新出现。
7. 核验资产记录逻辑删除且存储对象不可访问；若清理失败，核验只有脱敏服务端日志且声音仍不可见。

## 11. 完成定义

- 用户能够经二次确认删除自己的单条声音，且任何转写状态均可删除。
- 公共声音不显示入口；其他用户、工作区或端类型无法通过直接 API 删除。
- 删除成功后播放、编辑、展开、筛选和分页状态收口正确，刷新不恢复声音。
- 后端使用独立删除权限、SQL 归属条件、逻辑删除和提交后资产清理，不检查业务引用。
- 后端在最终条件删除中拒绝 `public`，声音和资产数据库可访问性原子关闭；物理对象清理不宣称具备崩溃后
  自动重试。
- 已领取转写结果不能写回已删除声音；资产清理失败不会复活或暴露声音。
- 前端、Java、SQL 契约、权限反向场景、两个启动应用路由边界和人工验收均有实际验证证据；未运行项必须明确列出，不能描述为完成。
